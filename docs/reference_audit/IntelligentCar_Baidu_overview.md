# IntelligentCar_Baidu 静态审计总览

## 结论

- 审计对象：`third_party/IntelligentCar_Baidu/`
- 锁定版本：`be05851d04154d374e46687e10809e13e997f712`
- 原项目：第十九届智能车竞赛百度完全模型组，仓库 README 明确描述 `EDGEBOARD赛事专用版` 上位机与 `TC264` 下位机通信。
- 对本项目状态：`REFERENCE_ONLY`。它不是“智慧城市无人驾驶算法应用赛”官方工程，任务元素、硬件、协议和参数都不能直接迁移为当前事实。
- 源码复用：禁止。根目录无许可证文件，且部分文件带“内部使用/请勿商用”声明；详见许可证审计。

## 构建系统与入口

- `race/CMakeLists.txt`：CMake 3.5、C++14，生成 `INCAR.RUN`。
- `race/src/main.cpp`：比赛程序入口。
- `self/CMakeLists.txt`：CMake 3.5、C++14，生成补充库演示 `SWAN.RUN`。
- `race/tool/compile.sh` 和 `init.sh` 会删除相对路径下的构建或图像目录；为保持第三方工作树不变，本次未执行。

## 运行数据流

根据 `race/src/main.cpp`、`libimage_process.cpp`、`path_side_search.cpp` 和 `libdata_process.cpp`：

1. 交互选择 `config/config_0.json`、`config_1.json` 或 `config_2.json`。
2. OpenCV `VideoCapture` 从示例视频或 V4L2 设备取流，采集线程维护一个单帧队列。
3. 图像灰度化、OTSU 二值化、Sobel 边缘处理，可选膨胀/腐蚀，并在 320×240 图上加边框。
4. 八邻域法从左右种子增长提取边线；逐行从中心向左右搜索边界，左右边界中点经一阶滤波形成路径线。
5. 拐点/弯点数量用于判断普通、十字和圆环赛道；模型结果用于桥梁、斑马线、危险区、救援区等原赛题区域。
6. 路径前瞻点生成 `ServoDir`/`ServoAngle`，赛道类型选择 `MotorSpeed`；字段通过原项目串口帧传给下位机。
7. 图像显示/保存和终端打印受 JSON 开关控制。

## 摄像头接口和图像处理

- `race/lib/libimage_process.cpp` 把 `CAMERA_EN` 映射为 `../img/sample.mp4`、`/dev/video0` 或 `/dev/video1`，使用 `CAP_V4L2`。
- 代码硬编码请求 320×240、MJPG 和调用方给出的 120 FPS；这些只能描述该第三方项目，不能成为本项目相机配置。
- `ImgUnpivot` 中还存在固定的透视变换点，但主预处理路径没有证据表明这些点经过当前赛题实车标定。
- 边线/中心线算法依赖固定图像坐标、像素阈值和第三方 JSON 参数，必须基于当前相机、车体和赛道重新设计与验证。

## 目标检测

- `race/lib/libmodel_ppnc.cpp` 与 `race/include/model/detection.hpp` 组合 PPNC 推理、ONNX 后处理和 PPNC NMS。
- 模型目录含 `deploy_paddle.*`、`post.onnx`、`nms.tar(.so)`、`io_paddle.json` 和 `label_list.txt`，并有多个模型变体。
- 预处理固定为 320×320：BGR 转 RGB、缩放、归一化和 ImageNet 均值/方差；检测分数阈值在第三方类中为 0.5。
- 标签包含 bomb、bridge、cone、crosswalk、evil、patient、spy 等原比赛语义，与当前赛题官方任务集合不一致。
- `buildNms` 会调用系统 `tar` 和 `g++` 动态生成共享库，依赖目标环境和随仓库二进制产物。

## 多线程与状态结构

- 明确创建并分离摄像头采集线程、模型推理线程和终端保护线程。
- 主线程在串口接收、图像处理、决策、赛道动作和串口发送状态之间循环。
- 圆环状态为 `IN_PREPARE/IN/OUT_PREPARE/OUT/OUT_2_STRIGHT/INIT`；模型区域为 bridge/crosswalk/danger/rescue/chase。
- 线程共享 `Img_Store`、推理结果和布尔标志。摄像头队列使用互斥锁，但推理结果/标志未见一致的同步原语；多处忙等，存在数据竞争、CPU 占用和失效无法超时的问题。
- `main.cpp` 中 `if (ThreadModelDetection_EN == true);` 后有分号，导致后续语句块无条件执行，是明确的静态风险。

## 串口、帧与控制量

- 该仓库在 `/dev/ttyUSB0` 和 `/dev/ttyUSB1` 间尝试，波特率宏为 115200，调用参数为 8 数据位、无校验、1 停止位。
- 发送帧实际为两个头字节、六个数据字节和固定尾字节；接收帧为两个头字节、三个数据字节和固定尾字节。名为 `CRC16` 的字段只是常量 `0xA2`，代码没有 CRC16 计算。
- 发送数据语义为舵机方向、舵机角度、电机速度、赛道类型、控制权转移、救援车库方向；接收语义为控制权、陀螺仪状态、比赛使能。
- 字段最终缩窄到单字节，单位、符号范围、溢出行为和真实执行器标定没有完整协议文档。

以上串口设备、速率、帧和控制量仅是第三方事实，当前项目不得采用。

## 停车、避障和日志

- 原项目没有当前规则所描述的停车场任务闭环。`Rescue_Zone` 根据锥桶平均图像纵坐标转移控制权给下位机，属于原“救援区/车库”语义。
- `Crosswalk_Zone` 用帧计数状态将电机速度设为 0；不存在当前赛题真实制动距离或停车保持时间证据。
- `Danger_Zone` 在二值图中为检测框画圆/线形成绕障路径，并按图像纵坐标放大舵机角度；大量半径、倍率和阈值来自第三方配置。
- 日志主要是 `std::cout`、可选图像保存和终端清屏打印；没有结构化时间戳、错误码、持久化轮转或磁盘写满处理。

## 可能不适用与风险

- 比赛任务语义不同：原项目包含圆环、桥梁、危险区、救援区、追逐区等，不等于当前任务。
- 硬件边界不同：明确适配 Edgeboard 赛事版与 TC264，不等于当前未知赛具。
- 构建依赖 Linux/V4L2/termios、固定 `/usr/local` 目录、PPNC 和预编译库。
- 配置含大量像素、帧数、速度和转向倍率硬编码，来源和标定记录不完整。
- 代码存在忙等、分离线程、共享状态数据竞争、潜在除零、固定缓冲区和异常直接 `abort()` 等工程风险。
- 没有测试框架、需求追踪、结构化安全监督或当前赛题合规证据。
